1.1 THE MASTER GAUNTLET RUNNER ARCHITECTURE
----------------------------------------------------------------------------------------------------
The master runners (`0AllUltrasDUCK.cs`, `0AllUltras7DUCK.cs`, `VoidDailiesDUCK.cs`) execute sets of
bosses sequentially based on four fundamental principles:
1. Zero User Configuration: Runs immediately with optimal defaults without modal dialog popups.
2. Dynamic Discovery: Any squad of accounts from an arbitrary pool form an army without hardcoded usernames.
3. Universal Consensus: If all accounts have already completed a daily or weekly boss quest, that boss
   is completely skipped from the run queue. If even 1 account needs a boss, all accounts will fight
   it together to ensure completion.
4. Atomicity & Lockstep: Each boss is executed as an isolated sub-session. State is cleansed in the
   player's house between boss transitions using the Oracle aura reset technique.


1.2 DYNAMIC MULTI-CLIENT ROSTER DISCOVERY (Duck.DiscoverParty)
----------------------------------------------------------------------------------------------------
Instead of hardcoding player usernames in the script (e.g. player1 = "acc1"), each client publishes
a timestamped heartbeat record to a shared sync file:
  `username:PRESENCE:unixTimestamp`

How it works:
1. Each client writes its presence line to `<SkuaOptionsDIR>/<syncFileName>`.
2. The client polls the file every 500ms and filters out entries older than 30 seconds.
3. Once the target number of distinct active accounts is found, all clients sort the usernames alphabetically:
   `sortedPlayers = [boessay, dagir487, okinahiru, rukiafeet1245]`
4. Because the sorting algorithm (`StringComparer.OrdinalIgnoreCase`) is deterministic across all
   machines, every account assigns the exact same player indices:
   - Player 1: boessay (Session Leader)
   - Player 2: dagir487
   - Player 3: okinahiru
   - Player 4: rukiafeet1245
5. This guarantees that Player 1 is always unambiguously identified on all machines.


1.3 PARTY CONSENSUS & BITMASK REQUIREMENT EXCHANGE
----------------------------------------------------------------------------------------------------
Every Ultra boss is assigned a unique bit flag:
  - Ezrajal:   1 << 0  (1)       - Drago:    1 << 5  (32)
  - Warden:    1 << 1  (2)       - Nulgath:  1 << 6  (64)
  - Engineer:  1 << 2  (4)       - Dage:     1 << 7  (128)
  - Tyndarius: 1 << 3  (8)       - Darkon:   1 << 8  (256)
  - Drakath:   1 << 4  (16)      - Gramiel:  1 << 9  (512)
                                 - Speaker:  1 << 10 (1024)

1. Each client queries its local game server status:
   `if (!Bot.Quests.IsDailyComplete(questId)) myRequiredMask |= ultraBit;`
2. Each client broadcasts `ULTRA_REQUIRED_<bit>` to the shared lockstep sync file for each needed boss.
3. All clients sync on `COMPLETION_MASK_READY`.
4. Each client reads the broadcasted signals from all players and performs a bitwise OR:
   `partyRequiredMask |= ultraBit;`
5. The resulting integer represents the absolute consensus queue of bosses needed by the party.


1.4 DYNAMIC GREEDY AUTO-ASSIGNMENT ENGINE (Duck.AutoAssignAndEquip)
----------------------------------------------------------------------------------------------------
Before each boss fight, the team must assign optimal classes and Forge enhancements to the accounts.
The framework solves this as a Constraint Satisfaction Problem:

1. Slot Requirements: Each boss defines slots with candidate classes and Forge requirements:
   ```csharp
   private static readonly DuckSlotRequirement[] TyndariusSlots = new[]
   {
       new DuckSlotRequirement { CandidateClasses = new[] { "Verus DoomKnight", "Arcana Invoker", "King's Echo", "Void Highlord", "Legion Revenant" } },
       new DuckSlotRequirement { CandidateClasses = new[] { "StoneCrusher", "ArchFiend" } },
       new DuckSlotRequirement { CandidateClasses = new[] { "ArchPaladin" } },
       new DuckSlotRequirement { CandidateClasses = new[] { "Lord of Order" } }
   };
   ```

2. Capability Probing:
   Each client probes its inventory AND bank for all candidate classes. If a class is in the bank,
   it automatically unbanks it (`Core.Unbank(cls)`). It also probes unlocked Forge enhancements.
   It publishes its capability payload:
   `READY|Classes=ArchPaladin,Lord of Order,StoneCrusher,Verus DoomKnight|Enh=Valiance,ArcanasConcerto,Dauntless`

3. Deterministic Greedy Match:
   - Slots are ordered by constraint difficulty (Forge requirement first, then fewest candidate accounts).
   - Most-constrained player accounts are matched first.
   - All clients run the exact same greedy matching algorithm over the sorted player list.
   - Result: All accounts independently reach the identical assignment mapping without master-slave network lag.


1.5 DETERMINISTIC ROOM JOINING (Duck.JoinRoom)
----------------------------------------------------------------------------------------------------
Flash / Skua map joining has an auto-correct feature where joining a map from a public room can cause
Skua to randomly change the room number to a public overflow room (e.g. `ultraezrajal-98432`).

To prevent room deviation:
```csharp
public void JoinRoom(string map, int roomNumber, string cell = "Enter", string pad = "Spawn")
{
    Core.PrivateRooms = true;
    Core.PrivateRoomNumber = roomNumber;
    string target = $"{map}-{roomNumber}";

    for (int i = 0; i < 10 && !Bot.ShouldExit; i++)
    {
        if (string.Equals(Bot.Map.FullName, target, StringComparison.OrdinalIgnoreCase))
        {
            if (!string.IsNullOrEmpty(cell) && !string.Equals(Bot.Player.Cell, cell, StringComparison.OrdinalIgnoreCase))
                Core.Jump(cell, pad);
            return;
        }

        Bot.Wait.ForActionCooldown(GameActions.Transfer);
        Bot.Map.Join(target, cell, pad, autoCorrect: false); // STRICTLY FALSE
        Bot.Wait.ForMapLoad(map);
        Bot.Sleep(1000);
    }
}
```


1.6 4-PHASE LOCKSTEP PROTOCOL (STEP -> ARRIVED -> CONTINUE)
----------------------------------------------------------------------------------------------------
Within an active boss session, all state transitions (Setup, Safe Room, Reset, Finish) are guarded
by the 4-phase lockstep protocol:
1. `STEP`: Player 1 writes `STEP|1.0|<sessionId>|<stepId>|<stepName>`.
2. `ARRIVED`: Every player (including Player 1) writes `ARRIVED|1.0|<sessionId>|<stepId>|<username>`.
3. `CONTINUE`: Player 1 monitors arrivals. Once all active players have arrived, Player 1 appends
   `CONTINUE|1.0|<sessionId>|<stepId>`.
4. `UNBLOCK`: Followers polling for `CONTINUE` see the continue record, record `lastArmyStepId`,
   and proceed simultaneously.

THE PRE-COMBAT BARRIER PRINCIPLE:
`Sync("FIGHT_READY")` executed while all accounts are assembled in `SafeCell` (`Enter`, `Spawn`) is the
FINAL synchronization barrier before engaging the boss.
CRITICAL MANDATE: NEVER place a lockstep barrier (such as `Sync("START_FIGHT")`) AFTER jumping into
the boss combat cell! Post-jump barriers create lethal deadlocks where the first player to load into the
cell takes immediate boss aggro and dies defenseless while waiting on file I/O for lagging followers.


1.7 HIGH-PERFORMANCE SKILL ENGINE (Duck.StartSkillEngine)
----------------------------------------------------------------------------------------------------
DUCK scripts use a custom asynchronous timer-based Skill Engine (`Duck.StartSkillEngine`) rather than
Skua's default skill handler:
- Runs in a background high-frequency loop (50-100ms tick).
- Supports skill priority weighting, cooldown checking, and mana thresholds.
- Supports skill suppression (e.g. stopping attacks when boss counter-shields are active).
- Automatically manages tonic, elixir, and combat potion (e.g. Felicitous Philtre) re-buffing during combat.


1.8 AURA-BASED COMBAT INTERRUPTS & TAUNTING ARCHITECTURE
----------------------------------------------------------------------------------------------------
Scroll of Enrage taunts must be executed with sub-second precision to control boss aggro and wipe mechanics.
The DUCK Framework provides three distinct taunt APIs with radically different internal concurrency behaviors:

1. `Duck.RequestTaunt(int mapId)`:
   - Sets a pending taunt flag (`pendingTauntMapId`).
   - On the next skill engine tick, if Skill 5 is ready, it equips the scroll and casts Skill 5.
   - NON-BLOCKING: Regular skills (heals, debuffs, buffs) continue to fire freely while waiting.
   - Best for: General boss taunts, add taunts, and non-fatal rotation hand-offs.

2. `Duck.RequestImmediateTaunt(int mapId)`:
   - Immediately checks if the player is alive, has the taunter role, and Skill 5 is ready (`Bot.Skills.CanUseSkill(5)`).
   - If ready, bypasses the normal skill queue to execute Skill 5 on the target instantly.
   - NON-BLOCKING: If Skill 5 is on cooldown, it does NOT block the skill engine.
   - Best for: Time-critical cyclic alternating taunts (Ultra Dage, Ultra Speaker, Ultra Tyndarius).

3. `Duck.RequestAbsolutePriorityTaunt(int mapId)`:
   - Sets `pendingAbsolutePriorityTauntMapId` and timestamp.
   - HARD-BLOCKING: The skill engine loop enters an exclusive polling loop (`Bot.Sleep(SkillPollDelay); continue;`).
     ALL OTHER SKILLS ARE HALTED until Skill 5 fires or a 3.5s timeout expires!
   - BEST FOR ONLY: Single-event threshold wipes (e.g. Ultra Warden at 500,000 HP) where casting ANY other
     skill could trigger global cooldown (GCD) and guarantee an instant 1-shot party wipe.

CRITICAL ANTI-PATTERN: THE ABSOLUTE PRIORITY TAUNT TRAP
NEVER use `RequestAbsolutePriorityTaunt` for cyclic, alternating taunt rotations (such as Ultra Dage or Ultra Speaker)!
Because `RequestAbsolutePriorityTaunt` completely freezes the skill engine until Skill 5 fires:
- ArchPaladin stops casting `Righteous Seal` (Skill 3), removing the -90% outgoing damage reduction on the boss.
- ArchPaladin stops casting `Hymn of Light` (Skill 2), cutting off healing to the squad.
- Auto-attacks and `Health Vamp` sustain halt completely during unhealable phases (e.g. *Noxious Decay*).
- Incoming un-mitigated boss burst wipes the entire party within seconds.
RULE: For all alternating taunts or multi-phase rotations, ALWAYS use `RequestTaunt` or `RequestImmediateTaunt`.
Reserve `RequestAbsolutePriorityTaunt` exclusively for single, non-cyclic threshold triggers.

4. `Bot.Target.GetAura(string auraName)` & Expiration Calculations:
   - Inspects target monster auras (e.g. `Focus`, `Righteous Seal`, `Counter Attack`).
   - Calculates exact seconds remaining using timestamp offsets:
     `double timeLeft = (DateTimeOffset.FromUnixTimeMilliseconds(aura.UnixTimeStamp).AddSeconds(aura.Duration) - DateTimeOffset.UtcNow).TotalSeconds;`
   - Allows seamless hand-offs (e.g. taunting when the current tank's `Focus` drops below 1.5s).


1.9 WIPE DETECTION, DEATH RECOVERY & SYNCHRONIZED RETRIES
----------------------------------------------------------------------------------------------------
If a party member dies or the fight encounters a wipe mechanic:
1. `RecoverFromDeath(fightAttempt, out bool recovered)`:
   - If player dies, sleeps in `RespawnPollDelay` (500ms) until `Bot.Player.Alive == true`.
   - Teleports to `SafeCell` (`Enter`, `Spawn`).
2. `HandleFightReset(fightAttempt)`:
   - Signals `FIGHT_RESET_<attempt>_SAFE` across all clients.
   - All clients re-group in the safe room, re-apply potions, and increment `fightAttempt`.
   - Retries up to `MaxFightAttempts` (3 to 5 attempts).


1.10 AUTHORITATIVE FINISH CHECKPOINT & CLEAN STATE TRANSITION
----------------------------------------------------------------------------------------------------
When the boss dies and kill credit is verified across the entire army:
1. All players jump to `SafeCell` (`Enter`, `Spawn`).
2. Each player turns in the quest: `Duck.CompleteUltraQuest(UltraQuestId)`.
3. All players synchronize on `Sync("FINISH")`.
4. Because `Sync("FINISH")` guarantees that all accounts have completed the turn-in and are safe,
   each script immediately marks `runResult = UltraRunResult.Completed` and exits.
5. The master runner executes `ResetBetweenUltras()`:
   - Teleports character to `/house`.
   - Equips `Oracle` class (cleansing all persistent boss auras from the AQW client cache).
   - Clears sync files for the next boss.


1.11 MULTI-CLIENT FILE LOGGING (duck_army.log)
----------------------------------------------------------------------------------------------------
AQW multi-client army scripts run across multiple background or minimized client windows. Skua's GUI console
(`Core.Logger`) outputs only to the active UI window and is invisible on background clients. Without persistent,
centralized file logging, diagnosing hangs, desyncs, or failed attempts across an army is impossible.

The DUCK Framework provides `Duck.FileLog(string message, string logPrefix = "")`:
- Thread-safe, non-blocking file writer to `Scripts/DUCKScripts/Logs/duck_army.log`.
- Automatically prepends high-resolution timestamp, active username, and script prefix:
  `2026-08-25 20:00:14.972 [boessay] [Ultra Tyndarius DUCK] Started as Player 1 (Lord of Order) in room 1245.`

MANDATORY LOGGING CHECKPOINTS:
Every ultra script MUST call `Duck.FileLog` at all critical state and lifecycle boundaries:
1. Script Start: Log player alias, assigned class, and room number.
2. Setup Completed: Log completion of class/enhancement/potion preparation.
3. Safe Room Entry: Log room join and fight attempt index.
4. Lockstep Sync Barriers: Inside `Sync(stepName)`, log entry and exit/status of every barrier.
5. Combat Jump: Log immediately upon jumping to the boss room.
6. Fight Lifecycle: Log fight start, player death/respawn, boss defeat, and wipe resets.
7. Verification & Finish: Log kill credit consensus result, quest turn-in, and completion.


1.12 "NO PLAYER LEFT BEHIND" CONSENSUS PROTOCOL (Duck.VerifyArmyKillCredit)
----------------------------------------------------------------------------------------------------
In AQW, if a player dies just before a boss is defeated, the game server may fail to award them the
drop or quest temp drop while they are in the respawn state.
Without a consensus protocol, the 3 or 6 surviving players would proceed to turn in and leave the room,
leaving the 1 dead player behind trapped in combat alone.

The DUCK Framework solves this via `Duck.VerifyArmyKillCredit`:
```csharp
bool myCredit = Bot.TempInv.Contains(BossDrop) || Bot.Inventory.Contains(PhysicalDrop)
                || Bot.Quests.CanComplete(UltraQuestId) || Bot.Quests.IsDailyComplete(UltraQuestId);

if (Duck.VerifyArmyKillCredit(fightAttempt, myCredit, armySize, LogPrefix))
{
    return true; // All players have credit; proceed to complete quest!
}

// Consensus failed: One or more players missed the drop
Core.Logger($"{LogPrefix} One or more players missed kill credit on attempt {fightAttempt}. Retrying fight with entire army...");
result = FightResult.Reset; // All players stay and retry together
```
How it works under the hood:
1. Each player evaluates `myCredit` and sends `KILL_CREDIT_OK_<attempt>` if true, or `KILL_CREDIT_FAIL_<attempt>` if false.
2. Every client waits up to 6 seconds for all `armySize` (4 or 7) players to report.
3. If ANY player sent FAIL (or timed out), `VerifyArmyKillCredit` returns `false` on ALL clients.
4. The entire army resets the fight and takes down the boss again together.


1.13 DROP HANDLING, BANK DETECTION & AC WHITELISTING CONVENTIONS
----------------------------------------------------------------------------------------------------
Every DUCK script MUST configure drop options in `ScriptMain` and `ExecuteScript`:
```csharp
Bot.Options.AcceptACDrops = true;
Bot.Options.RejectAllDrops = false;
```
Whitelisting Rules:
- Physical boss drops that must be kept in inventory (e.g. `Glacial Pinion`, `Sapphire Orb`, `Beast Soul`)
  must be whitelisted using `Bot.Drops.Add(...)` or `Core.AddDrop(...)`.
- Quest rewards that drop into the inventory upon quest completion (e.g. `Lineage of Devastation`, `Soul Sand`)
  must also be whitelisted so they are never rejected by Skua's drop manager.

Bank Item Detection Without Unbanking:
When stackable or AC items drop, Skua automatically routes and stacks them directly into the Bank if the
item already exists in the Bank. DUCK provides built-in utilities to evaluate quantities across Bag and Bank
without forcing unnecessary unbanking operations:
- `Duck.GetTotalItemQuantity(itemName)`: Returns `Bot.Inventory.GetQuantity(itemName) + Bot.Bank.TryGetItem(itemName)`.
- `Duck.CheckItemQuantity(itemName, targetQuantity)`: Returns `true` if `Core.CheckInventory(itemName, targetQuantity, toInv: false)`
  or `Duck.GetTotalItemQuantity(itemName) >= targetQuantity`.


1.14 SAFE ROOM VS. MULTI-ROOM MAP PREBUFFING RULES
----------------------------------------------------------------------------------------------------
Prebuffing behavior depends strictly on the map geometry:

1. **Type A: Dedicated Single-Room Ultras (Safe Entrance)**
   - Maps: `ultraezrajal`, `ultrawarden`, `ultraengineer`, `ultratyndarius`, `championdrakath`, `ultradrago`, `ultranulgath`, `ultradage`, `ultradarkon`, `ultragramiel`, `ultraspeaker`, `kala`, `astralempyrean`.
   - `Enter`, `Spawn` has NO monsters.
   - `Duck.GenericPrebuff()` (which casts Skills 3, 2, 1) is completely safe to run in `Enter`.

2. **Type B: Multi-Room Maps with Hostile Entrance Mobs**
   - Maps: `frozenlair` (Legion Lich Lord in `r3`), `sevencircleswar` (The Beast in `r17`).
   - `Enter`, `Spawn` contains hostile trash mobs (e.g. Frozen Knights).
   - **RULE**: `Duck.GenericPrebuff()` MUST NOT be called in `Enter`. Firing skills in `Enter` causes
     the bot to auto-target and fight trash mobs. In `PrepareSafeRoom()`, ONLY drink potions (`Duck.UsePotions(...)`).

3. **Type C: Single-Room Challenge / Entrance Bosses**
   - Maps: `icewing`, `deimos`.
   - Boss is directly in `Enter`, `Spawn`. ArchPaladin preps in place; party does not jump rooms.


1.15 TARGET ACQUISITION & THE CELL-ONLY ROOM STATE RULE (PAD-AGNOSTIC)
----------------------------------------------------------------------------------------------------
- **Dedicated 4-Player Ultra Maps**: Boss Map IDs are constant and invariant (e.g. `Tyndarius = 2`,
  `Engineer = 3`, `Drago = 2`, `Speaker = 1`). Using `Duck.MaintainTarget(int mapId)` is standard.
- **Multi-Room & Challenge Maps**: Map ID 1 usually belongs to a trash mob in `Enter`!
  Using `BossMapId = 1` causes the bot to target the mob in `Enter` rather than the boss in `r3`/`r17`.
  **RULE**: Always use `BossName` (string) for multi-room challenge bosses:
  ```csharp
  private const string BossName = "Legion Lich Lord";
  ...
  Duck.MaintainTarget(BossName);
  bool bossAlive = Duck.IsMonsterAlive(BossName);
  ```

THE CELL-ONLY ROOM STATE RULE (STRICT MANDATE):
When validating if the character is in the boss room or safe room (e.g. `IsInBossRoom()`), check
STRICTLY and ONLY the cell name using case-insensitive ordinal string comparison:
```csharp
private bool IsInBossRoom() =>
    string.Equals(Bot.Player.Cell, BossCell, StringComparison.OrdinalIgnoreCase);
```
CRITICAL PITFALL: NEVER check `Bot.Player.Pad == BossPad` in combat loops!
In Flash, when the bot moves (walking to coordinate safe spots, dodging boss attack zones, or receiving
knockback/push effects), the game engine updates or clears `Bot.Player.Pad`. If a script checks `Pad == BossPad`,
it evaluates to `false` even while standing directly next to the boss, causing repeated erratic `Core.Jump()`
calls in the middle of combat that reset skill GCDs and desynchronize the party.


1.16 OPENER DESIGN PATTERNS: JUMP-AND-ENGAGE VS. AP RIGHTEOUS SEAL
----------------------------------------------------------------------------------------------------
Entering combat against high-difficulty bosses requires choosing one of three standardized opener patterns
based on boss mechanics and map geometry:

1. **Pattern 1: Synchronized Jump-and-Engage Pattern** (Standard for 90% of Ultras & Challenge Bosses):
   - Maps: `ultraezrajal`, `ultrawarden`, `ultraengineer`, `championdrakath`, `ultradrago`, `ultranulgath`, `ultradage`, `ultradarkon`, `ultragramiel`, `ultraspeaker`, `kala`, `astralshrine`.
   - Used when the party can survive entrance aggro through group prebuffing and defensive HoTs.
   - **Protocol**:
     1. Entire army gathers in `SafeCell` (`Enter`, `Spawn`).
     2. `PrepareSafeRoom(preset)` drinks potions (`Duck.UsePotions`) and executes group prebuff (`Duck.GenericPrebuff()`).
     3. All clients synchronize on `Sync("FIGHT_READY")`.
     4. All clients start their combat systems / skill engine (`Duck.StartSkillEngine(...)`).
     5. All 4 to 7 players jump simultaneously to `BossCell` (`Boss` / `r2` / `r11a`, `Left`).
     6. All clients IMMEDIATELY enter `Fight(...)` and engage the boss without any post-jump barrier.

2. **Pattern 2: ArchPaladin Righteous Seal Opener Pattern** (For extreme early lethal-burst bosses):
   - Maps: `ultratyndarius`, `frozenlair` (Legion Lich Lord), `sevencircleswar` (The Beast).
   - High-burst bosses can 1-shot squishy party members upon entering. ArchPaladin must land `Righteous Seal`
     (Skill 3) to reduce outgoing boss damage by 90% before teammates enter combat.
   - **Protocol**:
     1. Entire army waits in `SafeCell` (`Enter`, `Spawn`), drinks potions, and syncs `FIGHT_READY`.
     2. **ArchPaladin**: Starts skill engine, jumps to `BossCell` (`r3` / `r17` / `Boss`), attacks boss,
        applies Righteous Seal, and broadcasts `Duck.SendArmySignal($"<BOSS>_SEAL_READY_{fightAttempt}")`.
     3. **Teammates**: Wait in `Enter`, `Spawn` until the signal is received, start their skill engines,
        jump to `BossCell`, and immediately engage combat.
     4. NO post-jump barrier is used!

3. **Pattern 3: External Safe Staging Pattern** (For single-room entrance bosses without safe staging):
   - Maps: `icewing`, single-room ultra instances where the boss is located directly in `Enter`, `Spawn`.
   - Prebuffing directly inside the entrance cell is unsafe because the boss aggros immediately.
   - **Protocol**:
     1. Entire army gathers in `yulgar-1245` (`Enter`, `Spawn`).
     2. `PrepareSafeRoom(preset)` drinks potions (`Duck.UsePotions`) and executes group prebuffing (`Duck.GenericPrebuff()`) in Yulgar.
     3. All clients synchronize on `Sync("FIGHT_READY")` in Yulgar.
     4. All 7 players jump simultaneously into the boss room (`Duck.JoinRoom(MapName, privateRoomNumber, "Enter", "Spawn")`).
     5. All clients immediately engage the boss with active buffs/HoTs from Yulgar without post-jump synchronization.
     6. On wipe or kill credit reset, the army retreats to `yulgar-1245` together to prebuff before re-entering.

====================================================================================================
CRITICAL ARCHITECTURAL ANTI-PATTERN: THE POST-JUMP IN-COMBAT DEADLOCK (`START_FIGHT`)
====================================================================================================
NEVER execute a lockstep barrier (`Sync("START_FIGHT")`) after jumping into the boss cell!
Here is the catastrophic sequence of events that occurs when post-jump synchronization is attempted:
1. In Flash/Skua, client map transitions take 200ms to 800ms. Player 1 (or the fastest PC) loads into `BossCell` first.
2. The boss immediately targets and attacks Player 1 with full combat aggro.
3. If Player 1 is halted inside `Sync("START_FIGHT")`, Player 1's main thread is locked in an I/O polling loop,
   waiting for the remaining players to load the map and write `ARRIVED`.
4. While locked inside `Sync("START_FIGHT")`, Player 1's skill engine has either not started or is deprived of
   thread updates. Player 1 takes lethal attacks and dies defenseless without firing heals or damage reduction.
5. With Player 1 dead, the lockstep barrier breaks or desyncs. The remaining players land into a wiped instance.
6. Under high combat packet stress, multi-client NTFS file access on `.sync` encounters file lock contention,
   further inflating synchronization delay.
GOLDEN RULE: `Sync("FIGHT_READY")` inside the safe room is the final pre-combat barrier. Once cleared,
clients jump and engage IMMEDIATELY. Combat synchronization inside the active boss cell is strictly prohibited!


1.17 CONTINUOUS FARM VS. SINGLE-KILL GAUNTLET ARCHITECTURE
----------------------------------------------------------------------------------------------------
AQW boss raiding divides fundamentally into two architectural paradigms:

1. **Single-Kill Atomic Gauntlets** (e.g. `0AllUltrasDUCK.cs`, `0AllUltras7DUCK.cs`, `VoidDailiesDUCK.cs`):
   - **Goal Metric**: Daily/Weekly quest completion (`Bot.Quests.IsDailyComplete(questId)`).
   - **Lifecycle**: Setup -> Prebuff -> 1 Boss Kill -> `VerifyArmyKillCredit` -> Quest Turn-in -> `Sync("FINISH")` -> Oracle Cleanse -> Next Boss.
   - **Consensus**: Binary (All accounts defeat the boss on Attempt N and transition together).

2. **Continuous / Repeatable Item Quantity Farms** (e.g. `NightmareCarnaxv4.cs`, `KingZedekv4.cs`, `ArmyPrismatasGoldFarmDUCK.cs`):
   - **Goal Metric**: Inventory quantity threshold (`Bot.Inventory.GetQuantity(item) >= targetQuantity`) or Gold Cap (`Bot.Player.Gold >= GoldCap`).
   - **Lifecycle**: Setup -> Prebuff -> Continuous Combat Loop across N respawns -> Local Item Check -> Cycle Lockstep -> Safe Room Staging (Sell/Turn-in/Restock) -> Global Army Consensus -> Exit.
   - **Consensus**: Distributed & Asynchronous (Drop RNG causes accounts to hit target quantities at different cycles; accounts must remain in combat and assist teammates until all 4 to 7 accounts reach consensus).


1.18 MULTI-MODE SCRIPT ARCHITECTURE: DAILY QUEST VS. QUANTITY FARM
----------------------------------------------------------------------------------------------------
To maximize code reuse, modern DUCK scripts support dual-mode execution:
```csharp
public enum FarmMode
{
    DailyOnce,         // Single-kill daily completion mode (used by Gauntlet Runners)
    FarmToQuantity     // Continuous farm mode (farms item drops/turn-ins up to TargetQuantity)
}
```
Execution Routing:
- **Master Runner Mode (`masterMode == true`)**: Forces `farmMode = FarmMode.DailyOnce`. The script runs a single synchronized kill attempt, completes the daily quest, cleans sync files, and returns `UltraRunResult.Completed` to the master runner.
- **Standalone Farming Mode (`masterMode == false`)**: Reads user options (or uses hardcoded quantities). Runs the continuous cycle loop until all army members achieve the target item quantity.

    public void ScriptMain(IScriptInterface Bot)
    {
        Bot.Skills.Stop();
        Bot.Options.InfiniteRange = true;
        Bot.Options.AcceptACDrops = true;
        Bot.Options.RejectAllDrops = false;

        try
        {
            Run();
        }
        finally
        {
            Duck.StopSkillEngine();
            masterMode = false;
        }
    }

    public UltraRunResult Run(bool isMasterMode = false, int masterRoomNumber = DefaultPrivateRoomNumber)
    {
        masterMode = isMasterMode;
        privateRoomNumber = masterRoomNumber;
        runResult = UltraRunResult.Failed;

        try
        {
            ExecuteScript();
        }
        finally
        {
            Duck.StopSkillEngine();
            masterMode = false;
        }

        return runResult;
    }

    private void ExecuteScript()
    {
        Bot.Options.AcceptACDrops = true;
        Bot.Options.RejectAllDrops = false;

        if (!masterMode)
        {
            int configuredRoom = Bot.Config?.Get<int>("PrivateRoomNumber") ?? DefaultPrivateRoomNumber;
            if (configuredRoom > 0)
                privateRoomNumber = configuredRoom;
        }

        if (!Duck.ValidatePrivateRoomNumber(privateRoomNumber))
            return;

        DuckAssignmentResult? assignResult = Duck.AutoAssignAndEquip(
            SyncFileName,
            BossSlots,
            armySize: TargetArmySize,
            timeoutSeconds: 120,
            allowDuplicates: false
        );

        if (assignResult == null)
            return;

        currentAssignResult = assignResult;

        if (!Duck.StartArmySyncDynamic(SyncFileName, assignResult.DiscoveredPlayers))
            return;

        ClassPreset preset = assignResult.Preset;
        playerAlias = $"Player {assignResult.PlayerNumber} ({preset.ClassName})";

        if (
            !Duck.ValidateUltraAccess(
                UltraQuestId,
                0,
                string.Empty,
                MinimumLevel,
                LogPrefix,
                preset.ClassName
            )
        )
            return;

        Duck.FileLog($"Started as {playerAlias} in room {privateRoomNumber}.", LogPrefix);
        Core.Logger($"{LogPrefix} started as {playerAlias} in room {privateRoomNumber}.");

        Bot.Drops.Add("Drop Item 1", "Drop Item 2");

        if (!Bot.Quests.IsDailyComplete(UltraQuestId) && !Bot.Quests.IsInProgress(UltraQuestId))
            Duck.AcceptUltraQuest(UltraQuestId);

        if (!Prepare(preset) || !Sync("SETUP_DONE"))
            return;

        if (!RunFightAttempts(preset) || !Sync("BOSS_DEFEATED"))
            return;

        Core.Jump(SafeCell, SafePad);
        if (Bot.Quests.CanComplete(UltraQuestId))
            Duck.CompleteUltraQuest(UltraQuestId);

        if (Bot.ShouldExit || !Sync("FINISH"))
            return;

        runResult = UltraRunResult.Completed;

        if (assignResult.IsLeader)
        {
            Bot.Sleep(1000);
            Duck.ClearAllSyncFiles(SyncFileName);
        }
    }

    private bool Prepare(ClassPreset preset)
    {
        Core.Logger($"{LogPrefix} {playerAlias} starting setup.");

        Duck.EquipClass(preset);
        if (Bot.ShouldExit)
            return false;

        Duck.PrepareEnhancements(
            preset.BaseEnhancement,
            preset.CapeEnhancement,
            preset.HelmEnhancement,
            preset.WeaponEnhancement,
            weaponFallbacks: preset.WeaponEnhancementFallbacks
        );

        Duck.PreparePotions(
            preset.Tonic,
            preset.Elixir,
            preset.CombatPotion
        );

        if (isTaunter)
            Duck.PrepareScrolls(EnrageScroll);

        if (Bot.ShouldExit)
            return false;

        Duck.FileLog($"{playerAlias} finished setup.", LogPrefix);
        Core.Logger($"{LogPrefix} {playerAlias} finished setup.");
        return !Bot.ShouldExit;
    }

    private bool PrepareSafeRoom(ClassPreset preset)
    {
        Duck.UsePotions(
            preset.Tonic,
            preset.Elixir,
            preset.CombatPotion
        );

        if (isTaunter)
            Duck.EquipScroll(EnrageScroll);

        // Note: GenericPrebuff() casts Skills 3, 2, 1 in SafeCell (call only if SafeCell is free of hostile mobs!)
        Duck.GenericPrebuff();

        return !Bot.ShouldExit;
    }

    private bool RunFightAttempts(ClassPreset preset)
    {
        for (int fightAttempt = 1; fightAttempt <= MaxFightAttempts && !Bot.ShouldExit; fightAttempt++)
        {
            Duck.JoinRoom(MapName, privateRoomNumber, SafeCell, SafePad);
            Duck.FileLog($"{playerAlias} joined {MapName}-{privateRoomNumber} for attempt {fightAttempt}.", LogPrefix);

            if (!PrepareSafeRoom(preset))
                return false;

            FightResult result;
            try
            {
                if (!Sync("FIGHT_READY"))
                    return false;

                // Start skill engine immediately before jumping to avoid pre-combat vulnerability
                Duck.StartSkillEngine(
                    preset.Skills,
                    playerAlias,
                    isTaunter,
                    LogPrefix,
                    preset.SkillMode,
                    maintainedPotion: preset.CombatPotion
                );

                // Pattern A: Standard Synchronized Jump (Default for most 4-7 man Ultras)
                Core.Jump(BossCell, BossPad);
                Duck.FileLog($"{playerAlias} jumped to {BossCell} for attempt {fightAttempt}.", LogPrefix);

                // Pattern B: ArchPaladin Solo Opener (Uncomment if boss 1-shots party upon entry)
                // bool isAP = string.Equals(preset.ClassName, "ArchPaladin", StringComparison.OrdinalIgnoreCase);
                // int apPlayerNumber = currentAssignResult?.GetPlayerNumberForClass("ArchPaladin") ?? -1;
                // if (isAP)
                // {
                //     if (!PrepareRighteousSeal(fightAttempt) || !SendRighteousSealSignal(fightAttempt))
                //         return false;
                // }
                // else
                // {
                //     if (apPlayerNumber > 0)
                //         WaitForRighteousSealSignal(fightAttempt, apPlayerNumber);
                //     Core.Jump(BossCell, BossPad);
                // }

                // NOTE: DO NOT place Sync("START_FIGHT") here! Engage the boss immediately upon jumping.
                result = Fight(preset, fightAttempt);
            }
            finally
            {
                Duck.StopSkillEngine();
            }

            if (result == FightResult.Defeated)
            {
                Duck.FileLog($"{playerAlias} confirmed {BossName} defeated on attempt {fightAttempt}.", LogPrefix);
                bool CreditCheck() =>
                    Bot.Quests.CanComplete(UltraQuestId) || Bot.Quests.IsDailyComplete(UltraQuestId);

                if (Duck.VerifyArmyKillCredit(fightAttempt, CreditCheck, TargetArmySize, LogPrefix))
                    return true;

                Core.Logger($"{LogPrefix} One or more players missed kill credit on attempt {fightAttempt}. Retrying fight with entire army...");
                result = FightResult.Reset;
            }

            if (result != FightResult.Reset || !HandleFightReset(fightAttempt))
                return false;

            if (fightAttempt >= MaxFightAttempts)
            {
                runResult = UltraRunResult.AttemptsExhausted;
                return false;
            }
        }

        return false;
    }

    private bool PrepareRighteousSeal(int fightAttempt)
    {
        Core.Logger($"{LogPrefix} {playerAlias} starting Righteous Seal preparation on {BossName}.");

        while (!Bot.ShouldExit)
        {
            if (!Bot.Player.Alive)
            {
                Core.Logger($"{LogPrefix} {playerAlias} died during Righteous Seal preparation.");

                while (!Bot.ShouldExit && !Bot.Player.Alive)
                    Bot.Sleep(RespawnPollDelay);

                if (Bot.ShouldExit)
                    return false;

                Core.Logger($"{LogPrefix} {playerAlias} respawned and is retrying preparation.");
            }

            if (!IsInBossRoom())
                Core.Jump(BossCell, BossPad);

            if (!Duck.IsMonsterAlive(BossName))
                return true;

            Duck.MaintainTarget(BossName);

            if (Bot.Target.GetAura("Righteous Seal") != null)
            {
                Core.Logger($"{LogPrefix} {playerAlias} confirmed Righteous Seal on {BossName}.");
                return true;
            }

            if (Bot.Skills.CanUseSkill(3))
                Bot.Skills.UseSkill(3);

            Bot.Sleep(FightPollDelay);
        }

        return !Bot.ShouldExit;
    }

    private bool SendRighteousSealSignal(int fightAttempt)
    {
        string signal = $"SEAL_READY_{fightAttempt}";
        if (!Duck.SendArmySignal(signal))
            return false;

        Core.Logger($"{LogPrefix} {playerAlias} sent {signal}.");
        return true;
    }

    private bool WaitForRighteousSealSignal(int fightAttempt, int apPlayerNumber)
    {
        string signal = $"SEAL_READY_{fightAttempt}";
        Core.Logger($"{LogPrefix} {playerAlias} waiting for {signal} from ArchPaladin (Player {apPlayerNumber}).");
        DateTime timeout = DateTime.UtcNow.AddSeconds(15);

        while (!Bot.ShouldExit && DateTime.UtcNow < timeout)
        {
            if (Duck.HasArmySignal(signal, apPlayerNumber))
            {
                Core.Logger($"{LogPrefix} {playerAlias} received {signal} from Player {apPlayerNumber}.");
                return true;
            }

            Bot.Sleep(FightPollDelay);
        }

        return !Bot.ShouldExit;
    }

    private FightResult Fight(ClassPreset preset, int fightAttempt)
    {
        Duck.FileLog($"{playerAlias} engaging {BossName} for attempt {fightAttempt}.", LogPrefix);
        bool bossObservedAlive = false;

        while (!Bot.ShouldExit)
        {
            if (Duck.ShouldResetFight(fightAttempt, DeathResetThreshold))
            {
                StopFightCombat();
                return FightResult.Reset;
            }

            if (!Bot.Player.Alive)
            {
                while (!Bot.ShouldExit && !Bot.Player.Alive)
                {
                    if (Duck.ShouldResetFight(fightAttempt, DeathResetThreshold))
                    {
                        StopFightCombat();
                        return FightResult.Reset;
                    }

                    Bot.Sleep(RespawnPollDelay);
                }

                if (Bot.ShouldExit)
                    break;

                if (!Duck.IsMonsterAlive(BossName) && bossObservedAlive)
                    break;

                if (Duck.ShouldResetFight(fightAttempt, DeathResetThreshold))
                {
                    StopFightCombat();
                    return FightResult.Reset;
                }

                // Cell-only room state check (pad-agnostic)
                if (!IsInBossRoom())
                    Core.Jump(BossCell, BossPad);

                continue;
            }

            bool bossAlive = Duck.IsMonsterAlive(BossName);
            if (bossAlive)
                bossObservedAlive = true;
            else if (bossObservedAlive)
                break;

            Duck.MaintainTarget(BossName);
            Bot.Sleep(FightPollDelay);
        }

        StopFightCombat();
        return (Bot.ShouldExit || !bossObservedAlive) ? FightResult.Stopped : FightResult.Defeated;
    }

    private void StopFightCombat()
    {
        Duck.StopSkillEngine();
        Bot.Combat.CancelTarget();
    }

    private bool HandleFightReset(int fightAttempt)
    {
        Duck.FileLog($"{playerAlias} executing fight reset for attempt {fightAttempt}.", LogPrefix);
        StopFightCombat();

        while (!Bot.ShouldExit && !Bot.Player.Alive)
        {
            Duck.ShouldResetFight(fightAttempt, DeathResetThreshold);
            Bot.Sleep(RespawnPollDelay);
        }

        if (Bot.ShouldExit)
            return false;

        Core.Jump(SafeCell, SafePad);
        return Sync($"FIGHT_RESET_{fightAttempt}_SAFE");
    }

    private bool IsInBossRoom() =>
        string.Equals(Bot.Player.Cell, BossCell, StringComparison.OrdinalIgnoreCase);

    private bool Sync(string stepName)
    {
        Duck.FileLog($"{playerAlias} syncing on {stepName}...", LogPrefix);
        bool success = Duck.SyncArmy(stepName);
        Duck.FileLog($"{playerAlias} sync {stepName} => {(success ? "SUCCESS" : "TIMEOUT/FAILED")}", LogPrefix);
        return success;
    }
}

5.1 ASYNCHRONOUS DROP RATES & THE "NO PLAYER LEAVES EARLY" PRINCIPLE
----------------------------------------------------------------------------------------------------
In repeatable challenge boss farming (e.g. Nightmare Carnax for Synthetic Viscera, King Zedek for
Atlas Regalia, or Archmage Prismatas for Elemental Binding), drops and quest turn-ins do not distribute
identically across all accounts simultaneously due to:
1. Skua drop pickup latency and server packet queue variance.
2. Unequal starting inventories (e.g. Account 1 already had 40/100 items, while Account 4 had 0/100).
3. Temporary quest drop RNG.

The "Desynchronization Disaster":
If Account 1 reaches 100 items and immediately runs `MoveToHouse()` and disconnects, the remaining accounts
lose their Lord of Order / ArchPaladin buffs or primary DPS. The remaining squad quickly wipes and becomes
permanently soft-locked.

THE UNIVERSAL DUCK RULE FOR CONTINUOUS FARMING:
"No account leaves combat alone. An account that satisfies its local item threshold MUST remain in combat,
maintain target acquisition, and execute its full skill engine rotation until EVERY squad member has
verified completion."


5.2 THE 2-TIER DISTRIBUTED SIGNAL CONSENSUS PROTOCOL
----------------------------------------------------------------------------------------------------
Continuous item farming operates via a 2-tier lockstep consensus mechanism:

```mermaid

5.3 CYCLE BATCHING, INVENTORY CONSTRAINTS & SAFE ROOM SYNCHRONIZATION
----------------------------------------------------------------------------------------------------
Certain items have strict stack limits (e.g. `Elemental Binding` caps at 2,500, but is sold in batches of
100 for optimal gold farming). Continuous scripts divide farming into discrete **Cycles**:

1. **In-Combat Phase (`FarmCycle`)**:
   - Entire army fights in `BossCell` / `FightCell`.
   - Each player tracks `Bot.Inventory.GetQuantity(dropItem) >= BatchQuantity`.
   - When reached, sends `CYCLE_{cycle}_READY` and keeps fighting.
   - When `AllPlayersSignaled($"CYCLE_{cycle}_READY")` is true, combat safely ends.

2. **Safe Room Staging Phase (`RunSafeRoomStage`)**:
   - Entire army jumps to `SafeCell` (`Enter`, `Spawn`).
   - Sells batch items or turns in refreshable quests.
   - If gold or total items meet the grand objective, sends `CYCLE_{cycle}_COMPLETE`.
   - Synchronizes on `Sync($"CYCLE_{cycle}_SAFE_DONE")`.

3. **Army Consensus Evaluation**:
   - Evaluates `armyComplete = AllPlayersSignaled($"CYCLE_{cycle}_COMPLETE")`.
   - If `armyComplete == true`: Transitions to `/house`, syncs `PARKED`, and exits.
   - If `armyComplete == false`: Restocks potions (`Duck.UsePotions(...)`), increments `farmCycle++`, and returns to `BossCell`.


5.4 REFRESHABLE QUESTS VS. DAILY TURN-INS
----------------------------------------------------------------------------------------------------
Standard Ultra scripts rely on daily quests (`Bot.Quests.IsDailyComplete(questId)`). Repeatable challenge
bosses (e.g. Nightmare Carnax quest 8872, King Zedek quest 10137) use **Refreshable Quests**.

Handling Strategies:

1. **Strategy A: Passive Auto-Registration (`Core.RegisterQuests`)**:
   - Best for fast single-monster drop loops where the player does not need to leave the room.
   - In setup: `Core.RegisterQuests(QuestId);`
   - Skua's background quest manager automatically accepts the quest and turns it in upon every kill.
   - The combat loop monitors the resulting reward item quantity:
     `bool isDone = Bot.Inventory.GetQuantity(RewardItem) >= TargetQuantity;`

2. **Strategy B: Synchronized Batch Safe-Room Turn-In (`Core.EnsureComplete`)**:
   - Best for bosses that require leaving combat to turn in or when managing inventory sell cycles.
   - In combat: Collects required temporary or physical drop items.
   - In safe room: `Core.EnsureComplete(QuestId); Core.EnsureAccept(QuestId);`

### Step 5: Implement Continuous Combat with Distributed Consensus

1. Executes the ArchPaladin Righteous Seal opener for safe entry.
2. Loops continuously across boss respawns.
3. Evaluates inventory + bank quantity using `Duck.CheckItemQuantity("Sapphire Orb", targetQuantity)`.
4. When reached, broadcasts `Duck.SendArmySignal("SAPPHIRE_ORB_GOAL_REACHED")`.
5. **Stays in combat** to maintain buffs and DPS for party members who have not yet reached the drop goal.
6. Breaks combat only when `AllPlayersSignaled("SAPPHIRE_ORB_GOAL_REACHED")` is true across all 7 accounts.

private bool RunContinuousDropFarm(ClassPreset preset, int targetQuantity)
{
    bool isAP = string.Equals(preset.ClassName, "ArchPaladin", StringComparison.OrdinalIgnoreCase);
    int apPlayerNumber = currentAssignResult?.GetPlayerNumberForClass("ArchPaladin") ?? -1;

    Duck.JoinRoom(MapName, privateRoomNumber, SafeCell, SafePad);
    if (!PrepareSafeRoom(preset))
        return false;

    if (!Sync("FIGHT_READY"))
        return false;

    if (isAP)
    {
        if (!PrepareRighteousSeal(1) || !SendRighteousSealSignal(1))
            return false;
    }
    else
    {
        if (apPlayerNumber > 0)
            WaitForRighteousSealSignal(1, apPlayerNumber);

        Core.Jump(BossCell, BossPad);
    }

    if (Bot.ShouldExit || !Sync("START_FIGHT"))
        return false;

    Duck.StartSkillEngine(
        preset.Skills,
        playerAlias,
        false,
        LogPrefix,
        preset.SkillMode,
        maintainedPotion: preset.CombatPotion
    );

    string readySignal = "SAPPHIRE_ORB_GOAL_REACHED";
    bool readySignalSent = false;
    bool deathLogged = false;

    while (!Bot.ShouldExit)
    {
        if (!Bot.Player.Alive)
        {
            if (!deathLogged)
            {
                Core.Logger($"{LogPrefix} {playerAlias} died during Sapphire Orb farm.");
                deathLogged = true;
            }
            Bot.Sleep(RespawnPollDelay);
            continue;
        }

        if (deathLogged)
        {
            Core.Logger($"{LogPrefix} {playerAlias} respawned and returned to combat.");
            deathLogged = false;
            Core.Jump(BossCell, BossPad);
        }

        if (!readySignalSent && Duck.CheckItemQuantity("Sapphire Orb", targetQuantity))
        {
            if (!Duck.SendArmySignal(readySignal))
                return false;

            readySignalSent = true;
            Core.Logger($"{LogPrefix} {playerAlias} reached {targetQuantity} Sapphire Orbs and continues fighting to assist teammates.");
        }

        if (readySignalSent && AllPlayersSignaled(readySignal))
            break;

        if (Duck.IsMonsterAlive(BossName))
            Duck.MaintainTarget(BossName);

        Bot.Sleep(FightPollDelay);
    }

    StopFightCombat();
    return !Bot.ShouldExit;
}

```csharp
/*

//cs_include Scripts/CoreBots.cs
//cs_include Scripts/CoreAdvanced.cs
//cs_include Scripts/DUCKScripts/UltrasDUCK/CoreDUCK.cs
using System;
using System.Collections.Generic;
using System.Linq;
using Skua.Core.Interfaces;
using Skua.Core.Options;

#nullable enable

public class UltraRepeatableFarmDUCK
{
    public enum FarmMode
    {
        DailyOnce,
        FarmToQuantity
    }

    private IScriptInterface Bot => IScriptInterface.Instance;
    private CoreBots Core => CoreBots.Instance;
    private static readonly CoreDUCK Duck = new();

    private const string LogPrefix = "UltraRepeatableFarmDUCK";
    private const string SyncFileName = "UltraRepeatableFarmDUCK.sync";
    private const string MapName = "bossmap";
    private const string SafeCell = "Enter";
    private const string SafePad = "Spawn";
    private const string BossCell = "r2";
    private const string BossPad = "Left";
    private const string BossName = "Challenge Boss";
    private const string TargetItem = "Target Item Name";
    private const int TargetQuantity = 100;
    private const int BatchQuantity = 25;
    private const int RepeatableQuestId = 1234;
    private const int MinimumLevel = 80;
    private const int TargetArmySize = 4;
    private const int DefaultPrivateRoomNumber = 1245;
    private const int FarmPollDelay = 100;
    private const int RespawnPollDelay = 500;

    private string playerAlias = string.Empty;
    private int privateRoomNumber = DefaultPrivateRoomNumber;
    private bool masterMode;
    private bool originalLagKiller;
    private UltraRunResult runResult = UltraRunResult.Failed;
    private DuckAssignmentResult? currentAssignResult;

    public string OptionsStorage = "UltraRepeatableFarmDUCK";
    public bool DontPreconfigure = true;
    public List<IOption> Options = new();

    private static readonly DuckSlotRequirement[] FarmSlots = new[]
    {
        new DuckSlotRequirement { CandidateClasses = new[] { "Verus DoomKnight", "Legion Revenant" } },
        new DuckSlotRequirement { CandidateClasses = new[] { "StoneCrusher" } },
        new DuckSlotRequirement { CandidateClasses = new[] { "ArchPaladin" } },
        new DuckSlotRequirement { CandidateClasses = new[] { "Lord of Order" } }
    };

    public void ScriptMain(IScriptInterface Bot)
    {
        Bot.Skills.Stop();
        Bot.Options.InfiniteRange = true;
        Bot.Options.AggroMonsters = true;
        Bot.Options.AcceptACDrops = true;
        Bot.Options.RejectAllDrops = false;

        try
        {
            Run();
        }
        finally
        {
            Duck.StopSkillEngine();
            masterMode = false;
        }
    }

    public UltraRunResult Run(bool isMasterMode = false, int masterRoomNumber = DefaultPrivateRoomNumber)
    {
        masterMode = isMasterMode;
        privateRoomNumber = masterRoomNumber;
        runResult = UltraRunResult.Failed;
        originalLagKiller = Bot.Options.LagKiller;

        try
        {
            ExecuteScript();
        }
        finally
        {
            Duck.StopSkillEngine();
            Bot.Options.LagKiller = originalLagKiller;
            masterMode = false;
        }

        return runResult;
    }

    private void ExecuteScript()
    {
        if (!masterMode)
        {
            privateRoomNumber = DefaultPrivateRoomNumber;
            Bot.Options.LagKiller = true;
        }

        if (!Duck.ValidatePrivateRoomNumber(privateRoomNumber))
            return;

        DuckAssignmentResult? assignResult = Duck.AutoAssignAndEquip(
            SyncFileName,
            FarmSlots,
            armySize: TargetArmySize,
            timeoutSeconds: 120,
            allowDuplicates: false
        );

        if (assignResult == null)
            return;

        currentAssignResult = assignResult;

        if (!Duck.StartArmySyncDynamic(SyncFileName, assignResult.DiscoveredPlayers))
            return;

        ClassPreset preset = assignResult.Preset;
        playerAlias = $"Player {assignResult.PlayerNumber} ({preset.ClassName})";

        if (Bot.Player.Level < MinimumLevel)
        {
            Core.Logger($"{LogPrefix} requires level {MinimumLevel}.", LogPrefix, messageBox: true, stopBot: true);
            return;
        }

        Duck.FileLog($"Started as {playerAlias} in room {privateRoomNumber}.", LogPrefix);
        Core.Logger($"{LogPrefix} started as {playerAlias} in room {privateRoomNumber}.");

        Core.AddDrop(TargetItem);

        if (!Prepare(preset) || !Sync("SETUP_DONE"))
            return;

        bool armyComplete = false;
        int farmCycle = 1;

        while (!Bot.ShouldExit && !armyComplete)
        {
            if (!FarmCycleCombat(preset, farmCycle))
                return;

            if (!Sync($"CYCLE_{farmCycle}_BATCH_READY"))
                return;

            if (!RunSafeRoomStage(preset, farmCycle, out armyComplete))
                return;

            farmCycle++;
        }

        if (Bot.ShouldExit || !armyComplete)
            return;

        MoveToHouse();
        if (Bot.ShouldExit || !Sync("PARKED"))
            return;

        runResult = UltraRunResult.Completed;

        if (assignResult.IsLeader)
        {
            Bot.Sleep(1000);
            Duck.ClearAllSyncFiles(SyncFileName);
            Duck.FileLog("Session leader cleared all sync files.", LogPrefix);
            Core.Logger($"{LogPrefix} session leader cleared all sync files.");
        }
    }

    private bool Prepare(ClassPreset preset)
    {
        Core.Logger($"{LogPrefix} {playerAlias} starting setup.");

        Duck.EquipClass(preset);
        if (Bot.ShouldExit)
            return false;

        Duck.PrepareEnhancements(
            preset.BaseEnhancement,
            preset.CapeEnhancement,
            preset.HelmEnhancement,
            preset.WeaponEnhancement,
            weaponFallbacks: preset.WeaponEnhancementFallbacks
        );

        Duck.PreparePotions(preset.Tonic, preset.Elixir, preset.CombatPotion);

        if (Bot.ShouldExit)
            return false;

        Duck.FileLog($"{playerAlias} finished setup.", LogPrefix);
        Core.Logger($"{LogPrefix} {playerAlias} finished setup.");
        return true;
    }

    private bool FarmCycleCombat(ClassPreset preset, int farmCycle)
    {
        Duck.JoinRoom(MapName, privateRoomNumber, BossCell, BossPad);
        Core.Jump(BossCell, BossPad);

        Duck.StartSkillEngine(
            preset.Skills,
            playerAlias,
            false,
            LogPrefix,
            preset.SkillMode,
            maintainedPotion: preset.CombatPotion
        );

        Core.Logger($"{LogPrefix} {playerAlias} started combat cycle {farmCycle}.");

        string readySignal = $"CYCLE_{farmCycle}_READY";
        bool readySignalSent = false;

        while (!Bot.ShouldExit)
        {
            if (!Bot.Player.Alive)
            {
                while (!Bot.Player.Alive && !Bot.ShouldExit)
                    Bot.Sleep(RespawnPollDelay);

                if (Bot.ShouldExit)
                    break;

                Core.Jump(BossCell, BossPad);
            }

            if (!readySignalSent && ReachedCycleTarget())
            {
                if (!Duck.SendArmySignal(readySignal))
                    return false;

                readySignalSent = true;
                Core.Logger($"{LogPrefix} {playerAlias} reached batch threshold for cycle {farmCycle} and continues helping party.");
            }

            if (readySignalSent && AllPlayersSignaled(readySignal))
                break;

            if (Duck.IsMonsterAlive(BossName))
                Duck.MaintainTarget(BossName);

            Bot.Sleep(FarmPollDelay);
        }

        StopCombat();
        return !Bot.ShouldExit;
    }

    private bool ReachedCycleTarget() =>
        Duck.CheckItemQuantity(TargetItem, masterMode ? 1 : BatchQuantity);

    private bool IsGrandGoalComplete() =>
        Duck.CheckItemQuantity(TargetItem, masterMode ? 1 : TargetQuantity);

    private bool RunSafeRoomStage(ClassPreset preset, int farmCycle, out bool armyComplete)
    {
        armyComplete = false;
        StopCombat();
        MoveToSafeRoom();

        if (RepeatableQuestId > 0 && Bot.Quests.CanComplete(RepeatableQuestId))
            Core.EnsureComplete(RepeatableQuestId);

        MoveToSafeRoom();

        bool localComplete = IsGrandGoalComplete();
        string completionSignal = $"CYCLE_{farmCycle}_COMPLETE";

        if (localComplete && !Duck.SendArmySignal(completionSignal))
            return false;

        if (!Sync($"CYCLE_{farmCycle}_SAFE_DONE"))
            return false;

        armyComplete = AllPlayersSignaled(completionSignal);
        if (armyComplete)
        {
            Core.Logger($"{LogPrefix} confirmed every active account achieved the target item goal.");
            return true;
        }

        Duck.UsePotions(preset.Tonic, preset.Elixir, preset.CombatPotion);
        return !Bot.ShouldExit;
    }

    private void MoveToSafeRoom()
    {
        if (string.Equals(Bot.Map.Name, MapName, StringComparison.OrdinalIgnoreCase))
        {
            Core.Jump(SafeCell, SafePad);
            return;
        }

        Duck.JoinRoom(MapName, privateRoomNumber, SafeCell, SafePad);
    }

    private bool AllPlayersSignaled(string signal)
    {
        for (int p = 1; p <= TargetArmySize; p++)
        {
            if (!Duck.HasArmySignal(signal, p))
                return false;
        }
        return true;
    }

    private void StopCombat()
    {
        Duck.StopSkillEngine();
        Bot.Combat.CancelTarget();
    }

    private bool Sync(string step) => Duck.SyncArmy(step);

    private void MoveToHouse()
    {
        Bot.Send.Packet($"%xt%zm%house%1%{Bot.Player.Username}%");
        Bot.Wait.ForMapLoad("house");
    }
